# 素材爬取计划 · Asset Crawling Plan（P5，2026-11-06 立）

> 目标：让「艺术卡」不再是「徽记 + 校名 + 年份」三件套，而是有真正好看的图形素材可选。
> 原则：**机器只做采集与粗筛，审美判断交给人。** 抓到的每一张都先给用户过目，点头才描摹上板。

## 一、要抓什么（按价值排序）

| 类别 | 用途 | 检索关键词 | 期望格式 |
|---|---|---|---|
| 卡通/吉祥物线稿 | 主视觉（像 Hello Kitty 那种整幅图形） | 「吉祥物 线稿」「mascot outline svg」「卡通 IP 简笔」 | SVG > 1024 px PNG |
| 校徽/校名题字 | 徽记、校名书法 | 各校官网标识页、urongda 1024 px | PNG 透明底 |
| 装饰边框/纹样 | 外框、页眉页脚 | 「victorian frame svg」「和风纹样 svg」「banner ribbon svg」 | SVG |
| 校园地标 | 背面主图 | 「<校名> 主楼 线稿」「campus line art」 | 1024 px+ |
| 毛笔/手写字体 | 校训、签名 | 系统字库、开源书法字体（OFL） | TTF/OTF |

## 二、抓取与粗筛（脚本）

1. `crawl_assets.py`：按关键词从可商用/可二次创作的站点抓 SVG 与 PNG（记录来源 URL + 许可）。
2. `filter_assets.py`：自动剔除——
   - 有色背景、带水印、小于 800 px；
   - 线条过密（线宽 < 0.2 mm 等效）或过细的灰阶图；
   - 转成「二值线稿 + 0.06 mm 扫描线」后覆盖率 >35% 的（上板会糊成一片）。
3. 输出 `assets/candidates/` + `index.md`（缩略图墙：路径 / 来源 / 许可 / 自动评分）。

## 三、人工环节（不可省）

4. 用户在图墙里挑 1–3 张，明确「要哪一部分」（整幅 / 只取头部 / 只取边框）。
5. 我按挑中的图描摹，先出 60 px/mm 局部图给用户确认笔画是否完整。
6. 通过后才进板。

## 四、法律与体面

- 个人非商业使用；来源与许可逐条记在 `index.md`，商用前必须重查。
- **不描摹仍在版权保护期内的商业 IP 做售卖**（Hello Kitty 只作为工艺参考，不上板）。
- 优先 OFL / CC0 / 校方公开发布的标识。

## 五、落地顺序

1. 先把 `crawl_assets.py` 写出来（抓 + 存 + 记来源），跑 3 个关键词验证链路；
2. 再写 `filter_assets.py`（自动评分 + 图墙）；
3. 用 1 块新板实测「图墙挑选 → 描摹 → 上板」全流程；
4. 把这条链路写进 `skill/gift-pcb` 的 P1.5（素材库）阶段。

## 六、已知限制

- 抓取会受站点反爬限制，脚本要做退避与本地缓存；
- 线稿质量差异极大，**自动评分只能筛掉明显不能用的，不能替你决定好不好看**；
- 一件真实作品通常需要「主视觉 + 装饰 + 排版」三类素材，不要指望一张图解决。

## 七、落地状态（2026-11-06 已实现）

```bash
# 联网：只取 CC/PD（维基共享资源 API），逐条记来源与许可
python scripts/17-crawl_assets.py --keywords "panda line art;victorian frame" --out assets/candidates --limit 8
python scripts/17-crawl_assets.py --keywords "mascot outline" --svg          # 只找矢量
python scripts/17-crawl_assets.py --keywords "..." --dry-run                 # 先看会下什么

# 没网、或图已经存在本机
python scripts/17-crawl_assets.py --from-dir D:/pics --out assets/candidates

# 粗筛成图墙（改写成 index.md，带 ✅/❌ 和理由）
python scripts/18-filter_assets.py assets/candidates --target-mm 40
```

实测（2026-11-06）：

- `--keywords "panda line art"` → 下到 3 个 CC BY-SA 文件；`18` 判 1 个可用（`Panda_Mark.png`，透明底 30%、最细笔画 0.50 mm），
  两个地铁照片被剔（四角发暗 + 最细笔画 0.023 mm）；
- `--from-dir` 在本机样例上：透明底线稿判可用，300 px 暗底图报出四条理由（小 / 暗底 / 墨量过高）。

两个脚本**不做**的事：不判断好不好看、不替你选图、不描摹。
`18` 的评分只是"能不能上板"（尺寸 / 底色 / 墨量 / 最细笔画），四条都过才 ✅。

## 零、先扩词：三轴 × 媒介（2026-11-07 补）

直接搜"立冬 涂鸦"只能搜到别人已经在用的东西。要"新颖"，靠的是**把气质词和场景词拆开再组合**：

| 轴 | 词 |
|---|---|
| **对象** | 女孩子 · 朋友 · 同学 · 孩子 · 恋人 |
| **气质**（由对象联想） | 可爱 · 软萌 · 温柔 · 治愈 · 文艺 · 清透 · 手帐感 |
| **场景** | 冬天 · 立冬 · 初雪 · 冬至 · 生日 · 毕业 · 圣诞 |
| **材质/媒介** | 手帐 · 水彩 · 毛线 · 烫金 · 纸胶带 · 贴纸 · 印章 · 剪纸 · 图标 · 字体 |

组合方式：**气质 × 场景 × 媒介**，例如
「可爱 · 雪 · 贴纸线稿」「温柔 · 冬天 · 手绘图标」「治愈 · 猫 · 单色线描」。
一批 6–10 个词、分 3–4 批搜，回来全部过 `18-filter_assets.py`（尺寸 / 底色 / 墨量 / 最细笔画），
**筛出来的挑 3–5 张给用户看**——用户点头之后再描摹上板，不要自己替用户选。

判据：一个"可爱"的主题，至少要有 **12 个以上候选**才谈得上挑选；
只找到 1–2 张就开工，最后一定是"你自己想的"而不是"她想要的"。
